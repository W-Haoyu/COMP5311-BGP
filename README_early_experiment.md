# BGP 小型复现实验 01

本实验受 GILL 启发，但不是 GILL 算法的实现或论文数值复现。使用 RIPE RIS rrc00 的 2023-09-01 00:00 UTC 和 00:10 UTC 两个 MRT 更新文件，前者训练，后者测试。来源：https://data.ris.ripe.net/rrc00/2023.09/ 。

## 运行

在本目录执行：

```sh
.venv/bin/python src/experiment.py
```

依赖 Python 3.9 和 mrtparse 2.2.0；如需重新创建环境，可使用 `python3 -m venv .venv` 然后 `.venv/bin/pip install mrtparse==2.2.0`。默认随机种子 42，随机基线每个预算重复 100 次。运行会覆盖 results 下的同名结果文件。

## 方法

以 peer ASN 和 peer IP 的组合作为 VP；每条 BGP UPDATE 消息计入数据预算，包括撤销和 IPv6 更新。链路指标仅使用可解析的普通 IPv4 announcement 中仅包含 AS_SEQUENCE 的 AS_PATH，去除连续重复 ASN，将相邻 AS 对视为无向边。省略 AS_SET 和其他非常规路径。测试参考集合为该测试文件全部 VP 可观察的链路，不包括 RIB 快照。

按训练更新数的比例设定预算。贪心算法选择单位训练更新数带来最多新训练链路的 VP；随机基线将随机排列的 VP 按同一训练预算装入。两种方法选出的 VP 完整保留。只使用训练和测试中都出现的 VP。测试期实际更新量可能不同，因此不可将同一行视为严格相同测试预算的比较。该方法针对链路覆盖而设计，不能证明其他任务表现，也不是论文事件特征、锚点或过滤算法。

## 数据输出

- `results/summary.json`：计数、随机种子和限制。
- `results/results.csv`：各预算下贪心结果和 100 次随机结果。
- `results/selected_vps.json`：各训练预算选中的 VP。

解析器错误状态在遇到单条损坏或不支持的记录后必须清除；脚本统计并跳过这些记录。两段样本都仅有 5 条解析错误。首次测试中发现此问题，已修复并重新生成输出。

## 限制

两个短窗口来自同一收集器，只有 IPv4 UPDATE 的路径信息，不含 RIB 和跨收集器观察；不存在严格相同的测试预算或独立事件真值。训练期就已活跃且链路多的 VP 可能主导结果。结果只反映该样本，不能推广为全互联网覆盖率。需要扩大数据量、多时间窗口和收集器，并增加严格匹配测试数据量的比较，再研究结论是否稳定。
