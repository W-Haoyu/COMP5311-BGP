# 第三阶段：训练期预算与相关组原型

## 运行

在 coding 文件夹执行 `.venv/bin/python src/phase3.py`。需要已下载的 data/rrc00、data/rrc01 文件和 src/experiment.py、src/multicase.py，依赖 mrtparse 2.2.0。运行会覆盖本目录的结果文件；不下载数据。随机种子 42，每个场景 100 次随机排序。

## 实验 A：训练期估计成本

四个场景分别用 rrc00 和 rrc01 的 2023-09-01 00:00 → 00:10、01:00 → 01:10 UTC 文件。使用训练期观察的全部 VP、训练期链路和训练期 UPDATE 数，排序并打包所选 VP。训练预算是训练期所有 UPDATE 消息的 5%、10%、20% 或 40%。测试不参与 VP 选择或成本约束；报告测试期实际消息比例和 IPv4 AS 链路覆盖率。因此该离线模拟避免了使用未来成本，但并不保证测试数据量满足同一比例，也未实现实时硬性截断。test-only VP 可以出现在测试参考集合中，但无法被选中。不同方法的测试期开销可能不同，不能当作严格同预算比较。VP 排序按训练链路增益/UPDATE 数；随机按种子重复。详细记录为 online_runs.csv；online_metadata.json 给出数据规模。

## 实验 B：简化的相关组和重构

仅使用 rrc00 的 00:00 文件训练、00:10 文件测试。基于训练集选取更新量最高的 20 个满足至少 2 个时间组和 2 个 VP 的前缀，测试中可能没有更新。仅处理普通 IPv4 announcement：每条记录按前缀展开，特征是 VP、完整 AS_SEQUENCE、标准与大 community；不含撤销、其他 community 类别或 RIB。对于各前缀，按时间排序，以每个组首条时间为锚点切分互不重叠、跨度最多 100 秒的窗口，窗口内相同特征去重。训练中统计每组特征组合出现的次数；对已保留特征使用包含它的最高频组推断（同频采用确定性排序）；逐前缀贪心选择 VP，直到训练组中的特征级召回达到 94% 或 VP 耗尽。测试沿用训练所选 VP 和组，无法匹配历史特征时不生成相关推断。所有记录按组和特征集合计数，非原始 BGP 更新条数；推断集合包含直接保留的特征。测试分组和评估用于离线计算，窗口并非真实事件真值，且尚未按论文全部细节实现。

correlation_prefixes.csv 含每前缀训练召回、直接保留数、测试真实特征数、重构命中数和推断总数。correlation_metadata.json 保存参数、计数、所选 VP。总微平均召回=命中数/真实数，精确率=命中数/推断数；这两个指标不等于论文对 false positive rate 或重构能力的完整定义。直接保留的特征也纳入命中。不能把该结果与论文 94% 数值直接比较。

## 与论文差异

训练窗口仅一个五分钟更新文件而非两天；组构造为简化的非重叠窗口；仅少量前缀、一个收集器、两类 community，省略 withdrawal、跨前缀合并、完整锚点选择与 BGP 实时过滤；对 100 秒时间误差的处理也不是原文完整判定。用途是验证核心机制并暴露局限，不是完整复现。
