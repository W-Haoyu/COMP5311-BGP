# 一小时训练与锚点数量验证

## 范围与时间划分

- 数据：RIPE RIS rrc00，2023-09-01；源 https://data.ris.ripe.net/rrc00/2023.09/ 。
- 训练：00:00–01:00 UTC，12 个五分钟文件；原论文训练为两天。
- 实验范围：先前训练选出的 20 个 IPv4 前缀按字母排序后的前 5 个，仅普通 AS_SEQUENCE announcement；不是整个互联网或完整路由表。
- 锚点排序：此前依据 00:00–00:15 数据产生的 50 个图特征代理锚点；算法和输入为近似，见 `results/topology_anchor/README.md`。
- 数量选择：在 01:00 与 01:10 两个五分钟验证窗口，从 0、5、10、…、50 中选择。规则预先固定为每个窗口链路覆盖至少 85%，再选平均保留比例最低的数量。选中 40 个。
- 最终留出：冻结 40 个锚点和一小时训练所得原始方向规则，在 01:45、01:50 两个新的五分钟窗口各评估一次。同一天、同一收集器的相邻窗口不构成跨时间/跨地域普遍性验证。

## 结果与基线

过滤方案在 01:45 使用 1,956/2,804 条前缀级记录（69.76%），覆盖该文件 324 条可观察 AS 链路的 93.21%；01:50 使用 1,793/2,517（71.24%），覆盖 330 条链路的 93.64%。覆盖分母仅是相同测试窗口和五个前缀可从 announcement 提取的无向链路，不是完整互联网。

随机 VP 基线每次对整个 VP 的目标前缀记录进行选择，100 个随机序列，使用测试期实际记录数事后装入与过滤器相同的预算上限；平均实际保留比例分别为 69.52%、70.97%，链路覆盖率为 78.48%、79.32%。它利用了未来成本，是离线比较而非在线可部署方法，且粒度离散导致实际数据量略小。逐前缀记录随机采样的预算数量与过滤器完全相同，100 次的平均覆盖分别为 95.67%、95.88%；该基线可能拆分一条多前缀 BGP 消息，与 VP+前缀过滤的部署约束不同。

40 锚点数量与 85% 验证目标均属于额外实验选择，论文原方法按冗余分数停止；当前结果不表示论文过滤器的性能，也不表示高压缩。两个基线和较高保留率必须一起报告。

## 复现命令

在 coding 目录执行：

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -v
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python src/hour_training.py
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python src/anchor_sweep.py
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python src/anchor_update_baseline.py
```

命令会覆盖 `results/hour_training/` 和 `results/anchor_sweep/` 相应结果。快读器先用目标 IPv4 前缀的二进制 NLRI 标记筛选，再交给 mrtparse 解码；与完整解析器在 00:00 文件的 19,646 条所选记录逐条一致，并核对了 00:15 文件的 15,467 条数量，但其他文件尚未逐条核验。扫描前跳过的 MRT 解析错误无法计入 candidate_decode_errors，因此它不能用于估计整个文件解析错误数。

## 其他约束

逐条记录级指标不含 withdrawal、IPv6、AS_SET 等复杂路径；事件级图为 20 前缀截断 RIB 的无向近似，未实现论文的 2,250 个分层事件、原样 15 维有向拓扑特征和真实 BGP 会话。重构使用近似分组、匹配及时间去重；`coalesced` 是额外启发式，不是论文 GILL。结果仍是受限小型原型，并非论文完整复现。
