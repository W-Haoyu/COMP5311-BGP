# 本地 GILL 原型：状态与限制

## 执行

在 coding 文件夹运行 `.venv/bin/python src/pipeline.py`；测试运行 `.venv/bin/python -m unittest discover -s tests -v`。该实验使用 rrc00 的 2023-09-01 00:00 和 00:10 UTC 更新，训练集选择 20 个前缀，在测试文件回放 IPv4 announcements。结果写入 report.json 和 replay.csv。一次公告可以包含多个前缀，统计为前缀级记录而非 BGP 消息；非目标前缀不进入回放，因此不能将结果作为整个数据流的压缩率。

本次完善：跨前缀要求每个 VP 的属性及次数一致，按照属性对时间排序后逐项允许 100 秒误差；使用集合计算事件可见性差异；增加独立 JSONL 流过滤器 src/filter_stream.py（传 --policy 指向 report.json）。每行须有字符串 vp 和 prefix；已选择锚点优先保留、已列入丢弃集合的组合过滤、其他组合默认保留。数据标准化、源连接、重连和实时计时均由外部负责。可选 --discard-log 保存丢弃记录。它不是 BGP 对等进程，不生成 MRT；输入每行须代表一个前缀，不能直接把多前缀消息当作单个输入。

src/route_state.py 及 src/update_state.py 提供实验性的普通 IPv4 路由状态与路径替换、撤销、定向链路计数。当前尚未接入 pipeline，未装入 RIB；不处理 IPv6 MP_REACH/UNREACH、AS_SET 或复杂路径，不能当作完整实时 RIB。

## 严格限制

phase3 的相关组仍是以首条更新锚定的互不重叠 100 秒窗口、按签名去重的近似，不是论文完整重构算法；训练只有一个更新文件，不是论文的两天。锚点排序使用二值事件可见性代替论文的 15 维、逐事件标准化的 RIB 拓扑特征；成本使用训练前缀级公告数，非论文 365 个一小时窗口的 UPDATE 数。跨前缀匹配为保守近似，事件匹配的传递性和全序选择可能影响结果。锚点选择的得分缩放也不是论文每事件距离平均的完整实现。未对 AS 分类采样、跨收集器事件对齐和实时路由输入实现论文方案。不能称完整 GILL 或直接比较论文表 2。RIB 文件可从 https://data.ris.ripe.net/rrc00/2023.09/ 获取，bview.20230901.0000.gz 约 425 MB（压缩），但当前未下载或加载。
