# 独立窗口评估与消融

## 目的

验证先前训练的近似过滤规则和两组近似锚点在后续独立时间窗口的链路可见性。此实验不是完整 GILL 复现，也不能与论文表 2 的五项任务直接对比。

## 训练与测试

- 过滤规则和候选前缀来自 `results/pipeline/report.json`；近似拓扑锚点来自 `results/topology_anchor/summary.json`。
- 锚点从 00:00–00:15 UTC 的 RIB / 更新学习，最后一个被选事件结束于 00:13:53 UTC。
- 独立测试文件是 RIPE RIS rrc00 在 2023-09-01 的 00:15 和 00:20 UTC 两个五分钟更新文件。每个文件单独计算、使用相同的冻结规则和锚点。原始来源：https://data.ris.ripe.net/rrc00/2023.09/ 。
- 脚本检查测试窗口里所选记录的最早时间严格晚于所选锚点事件的结束时间；调用者仍应保留并核对预先训练的模型。两个相邻测试窗口可能相关，不能当作独立日期重复。

## 运行

在 coding 目录执行：

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -v
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python src/heldout_eval.py
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python src/heldout_eval.py --test-slot 0020 --output results/heldout_0020
```

运行覆盖各结果目录的 summary.json、random_runs.csv；`random_runs.csv` 对应 50 锚点方案。每个消融的随机比较均用种子 42 重复 100 次，消融随机结果在 summary.json 中保存平均值。需要先生成训练产物并下载测试文件。

## 口径和局限

仅从训练选定的 20 个前缀中提取 AS_SEQUENCE 可解析的普通 IPv4 announcement，并将一条包含多个前缀的通告展开为多个前缀级记录。测试文件中的全部此类记录构成参考集合。AS 链路由相邻 AS 提取为无向边，消除连续重复 ASN；链路覆盖率是保留记录包含的不同链路数除以该参考集合的不同链路数。它不是完整 RIB 或全球拓扑的覆盖率。忽略 withdrawals、IPv6 和不支持的路径，两份文件各有 5 条解析错误。

规则以 VP + 前缀应用，优先保留锚点，未知规则默认保留。三个消融分别不用锚点、使用以前的 35 个可见性代理锚点、使用 50 个小图特征代理锚点；它们不是三种完整论文方法。随机基线从前缀级记录中直接随机抽取与每个消融完全相同数量的记录，100 次取平均。它可以拆分真实 BGP 消息，不能当作同样部署约束的 VP+前缀过滤方案。两个窗口的数据预算分别不同，不能直接将不同方案的覆盖率当作相同预算比较。

## 结果解释

00:15 窗口中，不加锚点保留 3.94% 记录、链路覆盖率 15.34%，同数量随机记录平均 54.08%；35 个锚点保留 59.05%、覆盖 82.06%，同数量随机平均 95.69%；50 个锚点保留 94.10%、覆盖 99.85%，同数量随机平均 99.60%。00:20 窗口呈现类似模式，详细数值见 `../heldout_0020/summary.json`。高覆盖在 50 锚点方案下伴随很高的保留量，不能说明本原型达到了论文的数据效率；低锚点方案不如逐条随机基线也提示目前的相关组、过滤和代理锚点仍需改进。
